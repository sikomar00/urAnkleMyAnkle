# 최종 보고서 — 산업 기계 센서 기반 고장 위험 판별 대시보드

수치는 모두 괄호 안의 파일에서 가져왔습니다. 과제별 상세 표는 [`docs/MODEL_CARD.md`](../docs/MODEL_CARD.md)에 있습니다.

## 1. 개요

- **무엇을 만들었나:** 합성 산업 설비 데이터로 기계별 고위험일을 판별하고, 그 결과를 단순 기준선과 같은 분할에서 비교해 보여 주는 Dash 대시보드입니다.
- **데이터:** 기계 10대 × 부품 20종 × 1,095일, 219,000행입니다(`data/raw/synthetic_industrial_machine_data.csv`).
- **화면 4개**
  - ① 현황
  - ② 기계 상세
  - ③ 모델·예측
  - ④ 데이터
- **실행:** 로그인·DB 없이 `python -m src.wireframe_app` 하나로 실행합니다. 팀에서 만든 로그인·계정·MySQL 감사 로그 기능은 2026-10-03에 앱에서 떼어 `archive/legacy/`에 보관했습니다(7절).

| 로지스틱 회귀 | 0.613 | 0.622 |

**그래서 주 과제를 기계 단위 당일 고위험일 판별로 바꿨습니다.**
- 기계·일마다 고장 표시된 부품 중요도를 A=4·B=2·C=1로 합한 고장점수가 기준(12·13·14) 이상이면 고위험일입니다.
- 당일 센서를 입력으로 쓰므로 사전 예측이 아니라 판별입니다.
- 부품 단위 과제(7일 내, 당일, 부품군 진단)는 보조로 남겼습니다.

## 3. 아키텍처

```
data/raw/*.csv ──▶ src/ 학습·실험 (model_comparison.py 등) ──▶ outputs/*.csv
        │                                                        │
        └────────────▶ src/dashboard_data.py (읽기 전용 로더) ◀───┘
                                  │
                       src/ui/ (화면 ①~④ · 그림 · 보고서)
                                  │
                       src/wireframe_app.py (Dash 앱 · 콜백)
```

- **대시보드는 학습하지 않습니다.** 모델 결과는 `outputs/`의 CSV로만 받습니다.
- **디자인 토큰 한 벌을 CSS와 Plotly가 함께 씁니다.** `design/tokens.json`에서 `assets/00-tokens.css`(CSS 변수)와 `src/theme.py`(Plotly 템플릿 `plantfloor_light/dark`)를 함께 만듭니다. 그래서 차트와 화면이 같은 색을 씁니다.

## 4. 핵심 구현

1. **같은 분할의 모델·기준선 비교**(`src/model_comparison.py`, `src/baselines.py`)
   - 과제마다 기준 A(학습 구간 양성 비율)와 기준 B(기계 또는 기계×부품별 과거 비율)를 모델과 같은 시험 구간에서 계산합니다.
   - 지표는 AP·ap_lift·ROC-AUC, 컷오프 지표, 상위 10% 정밀도(동점은 기댓값), "항상 정상" 정확도입니다.
   - 영향 변수는 검증 구간 permutation importance(AP 기준)입니다.
2. **필터와 화면 상태**
   - 공장·기계 종류·기계·기간 필터가 저장소 한 곳(`filter-store`)을 거쳐 화면마다 적용됩니다.
   - 필터가 적용되지 않는 화면에서는 컨트롤을 비활성화하고 이유를 보여 줍니다.
3. **판정 임계값 재계산:** 화면 ③의 슬라이더는 저장된 예측 확률을 다시 이진화해 혼동행렬과 정밀도·재현율을 바로 갱신합니다. 모델은 다시 학습하지 않습니다.
4. **반응형 레이아웃:** 12열 그리드가 1280~1920px에서 늘고 줄며, 그보다 좁으면 "데스크톱 전용" 안내를 보여 줍니다. 1600px 미만에서는 헤더의 내보내기 메뉴를 팝오버로 접습니다.
5. **보고서 내보내기**
   - 독자별(공장 관리자·경영진·설비·데이터 분석가, `src/ui/base.py`의 `REPORT_AUDIENCES`) 섹션 골격으로 PDF·Excel을 만듭니다.
   - PDF는 시스템의 한글 TrueType을 찾아 임베드합니다. 찾지 못하면 글자 없는 PDF를 내보내지 않고 실패로 알립니다(`src/ui/report.py`).
6. **접근성:** Dash 기본 컴포넌트가 노출하지 않는 접근 이름·역할·키보드 탭 조작을 `assets/04-a11y.js`가 렌더된 DOM에 보충합니다.

## 6. 성과

**모델 (시험 구간)**
- **주 과제(기준 12)**(`outputs/machine_risk/comparison.csv`)

  | 모델 | AP | ROC-AUC |
  |---|---|---|
  | 기준 A | 0.116 | 0.500 |
  | 기준 B | 0.178 | 0.648 |
  | 로지스틱 회귀(운영 모델) | 0.298 | 0.759 |
  | 랜덤 포레스트(마감 제출본의 운영 모델) | 0.237 | 0.733 |
  | HGB | 0.259 | 0.745 |

  - 모든 모델이 기준 B를 넘습니다.
  - 운영 모델은 기준마다 검증 구간 AP 1위 모델이고, 세 기준(12·13·14) 모두 LR입니다. 마감 제출본은 RF(팀 결정)를 썼고, 같은 분할 재비교 후 2026-10-06에 바꿨습니다.
  - LR도 경보 100건 중 실제 고위험일은 약 26건이고, 영향 변수 1위는 공장(`plant_code`)입니다.
- **보조 과제 — 부품 7일 내**(`outputs/pf_within_7d/comparison.csv`): LR AP 0.613, 기준 B 0.611, RF 0.562로 기준선과 거의 같습니다.
- **보조 과제 — 부품 당일**(`outputs/current_state/comparison.csv`): HGB AP 0.153, 기준 B 0.129. 경보율이 0.575로 높습니다.
