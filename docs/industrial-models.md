# 산업기계 모델 실행

구현 파일: `src/data_huijae.py`. 원본 CSV와 기존 대시보드는 수정하지 않습니다.

```powershell
# 전처리 결과가 없으면 먼저 실행합니다.
./.venv/Scripts/python.exe -m src.prepare_machine_data
# 로지스틱 회귀와 Prophet을 실행합니다.
./.venv/Scripts/python.exe -m src.data_huijae
# 각각 실행할 수도 있습니다.
./.venv/Scripts/python.exe -m src.data_huijae --models logistic
./.venv/Scripts/python.exe -m src.data_huijae --models prophet --prophet-stride 1
```

이번에 만든 `.venv`는 Python 3.12 환경입니다. 기존 `venv`는 Python 3.11 실행 경로가 없어 별도로 보존했습니다. 설치 버전은 결과의 `run_versions.json`에 기록됩니다.

## 부품별 로지스틱 회귀

- 현재 고장 표시가 없는 부품의 **향후 7일 내 고장 표시 여부**를 예측합니다.
- 전처리의 `eligible_for_model`과 입력 허용 목록만 사용합니다. 당일 고장 표시·출고량·작업 지시·미래 정답은 입력에서 제외됩니다.
- 센서·부품 정보·엄격히 이전 날짜의 이력을 사용합니다. 결측값 보완·표준화·범주 변환은 학습 구간에만 맞춥니다.
- 학습 131,364행, 검증 28,327행, 테스트 28,514행입니다. 미래 7일 정답이 다음 구간을 침범하는 행은 제외합니다.
- 검증 F1이 최대인 판정 기준을 선택합니다. 동점이면 0.5에 가까운 값을 선택합니다. 테스트로 기준이나 모델 설정을 조정하지 않습니다.
- 학습 구간의 고장 표시 비율을 모든 행에 동일하게 부여하는 기준모델과 비교합니다. ROC-AUC는 순위를 구별하는 능력으로 0.5가 무작위 수준입니다. F1만으로 모델의 유용성을 판단하지 않습니다.
- 최신 날짜의 현재 정상 부품도 별도로 점수를 저장합니다. 이 점수는 합성 데이터에서 학습한 값이며 실제 현장의 고장 확률로 검증하거나 보정한 값이 아닙니다.
- 회귀계수는 입력과 점수의 관계이며 원인 설명이 아닙니다. 숫자 입력은 표준화된 단위이고 서로 비슷한 정보가 여러 열에 있어 계수 해석에 주의해야 합니다.

## 설비별 Prophet

- 기계·날짜당 한 행인 `machine_df`에서 날짜와 `power_consumption_kw`만 사용합니다. 단위가 kW이므로 다음 날 **전력값** 예측이며 일간 에너지(kWh) 예측이 아닙니다.
- 설비 10대에 각각 연간·주간 패턴을 사용하며, 미래 센서 실측값이나 근거 없는 공휴일은 입력하지 않습니다.
- 검증·테스트 각 구간의 첫날부터 기본 14일 간격 및 마지막 날을 평가합니다. **모든 날짜에 대한 평가가 아닌 표본 날짜의 다음 날 예측 평가**입니다. `--prophet-stride 1`이면 모든 날짜를 평가합니다.
- 평가 날짜 직전까지의 관측으로 다시 학습한 뒤 하루 앞을 예측합니다. 뒤쪽 평가 시점에는 앞쪽 테스트 날짜의 이미 관측된 전력을 사용할 수 있습니다. 설정은 고정하며 테스트 결과로 최적화하지 않습니다.
- 동일 날짜의 전날값 유지·7일 전 값 유지 방법과 MAE(평균 절대 오차), RMSE(큰 오차에 더 큰 가중을 주는 오차)를 비교합니다. 둘 다 kW이며 작을수록 좋습니다.
- 평가 후 전체 과거 자료로 설비별 최종 모델을 학습해 데이터 마지막 날짜 다음 날을 예측합니다. 이 미래 예측에는 아직 실제 정답이 없습니다. 예측구간은 생성하지 않습니다.

## 이번 데이터의 실제 로지스틱 결과

테스트 ROC-AUC는 **0.6236**, 평균 정밀도(AP)는 **0.6205**입니다. 기준모델 ROC-AUC는 0.5입니다.

검증 F1 기준으로 선택한 0.25에서는 검증·테스트 모두 전부 양성으로 분류합니다. 테스트 F1 0.6722는 전부 양성인 기준모델과 같으므로, 높은 F1만 보고 실용적인 경보 모델이라고 판단하면 안 됩니다. 이 판정 기준을 그대로 대시보드 경보에 연결하지 않습니다.

함께 기록한 고정 기준 0.5에서는 테스트 정확도 **58.86%**, 정밀도 **58.45%**, 재현율 **64.77%**, F1 **0.6145**입니다. 일부 구별 능력은 있으나 오경보와 놓치는 사례가 많습니다. 테스트 결과를 본 뒤 설정을 바꾸지는 않았습니다. 운영 판정 기준은 별도 검증 자료와 점검 비용·처리 가능한 경보 수를 정한 뒤 검토해야 합니다.

## 이번 데이터의 실제 Prophet 결과

설비 10대 × 검증 13일·테스트 13일로 총 260건의 하루 앞 예측을 평가했습니다. 다음 표는 테스트 표본 130건의 전체 오차입니다.

| 방법 | MAE(kW) | RMSE(kW) |
| --- | ---: | ---: |
| Prophet | 1.4699 | 1.8749 |
| 전날 값 유지 | 2.0833 | 2.7179 |
| 7일 전 값 유지 | 1.8742 | 2.5213 |

이 표본에서는 Prophet의 오차가 두 기준보다 작습니다. 모든 날짜나 실제 공장에서 같은 성능을 보장하는 결과는 아닙니다. 2025-01-02의 설비별 예측 10건과 최종 모델 10개도 저장했습니다.

검사 7개 통과, 모델 저장·복원 예측 일치, 분류 예측 56,841건 및 전력 평가 260건의 날짜·건수 확인을 완료했습니다. 실행 중 그래프용 글꼴 캐시 권한 및 선택 패키지 Plotly 안내가 있었지만, 수치 예측과 파일 생성은 완료됐습니다. 이 실행 환경은 모델 학습용이며 대시보드 실행에 필요한 전체 패키지를 설치한 환경은 아닙니다.
