# 부품 이력과 센서 비교 실험

구현: `src/data_huijae2.py`. 기존 `data_huijae.py`, 원본 CSV, 대시보드는 수정하지 않습니다.

## 실행

프로젝트 폴더에서 실행합니다.

```powershell
./.venv/Scripts/python.exe -m src.data_huijae2 --top-k 10
```

`src/data_huijae2.py`를 직접 실행해도 됩니다. 원본 경로는 기본적으로 Downloads의 `synthetic_industrial_machine_data.csv`이며 `--input 경로`로 바꿀 수 있습니다. 기존 `prepare_machine_data.py`의 전처리 함수를 재사용해 원본을 메모리에서 가공하며 원본과 이전 가공 파일을 덮어쓰지 않습니다.

결과는 `data/processed/industrial/ablation_results/실행시각/validation/`에 저장됩니다. `--run-dir 새폴더`로 위치를 지정할 수 있고, 기존 폴더를 덮어쓰지 않습니다. 각 실행에는 A/B/C 학습 모델과 입력 목록·설정·원본 해시를 기록한 `manifest.json`이 함께 저장됩니다.

시험 구간은 기본 실행에서 예측하거나 성능을 비교하지 않습니다. 실험 구성을 정한 뒤 해당 검증 실행의 폴더를 지정하면 저장한 모델과 점검 수를 그대로 사용합니다. 재학습·판정 기준 변경은 하지 않습니다.

```powershell
./.venv/Scripts/python.exe -m src.data_huijae2 --stage test --run-dir data/processed/industrial/ablation_results/실행시각
```

이번 작업에서는 실제 데이터의 시험 단계를 실행하지 않았습니다. 별도의 작은 합성 자료로 시험 단계의 작동은 검사했습니다. 다만 이전 `data_huijae.py` 작업에서 같은 시험 기간의 성적을 이미 확인했으므로 완전히 처음 보는 평가 자료라고 할 수는 없습니다.

## 비교 조건

| 실험 | 공통 부품 정보 | 고장 이력 | 센서 |
| --- | --- | --- | --- |
| A | 포함 | 포함 | 제외 |
| B | 포함 | 제외 | 포함 |
| C | 포함 | 포함 | 포함 |

- 공통 부품 정보: 부품 번호, 부품군, 중요도, 단위, 단가.
- 고장 이력: **설비+부품별** 전날까지 최근 7일·30일 표시일 수, 마지막 표시 이후 경과일, 이전 표시 관측 여부. 같은 번호의 부품이라도 설비가 다르면 이력을 섞지 않습니다.
- 센서: 당일 베어링 온도, 모터 온도, 수평·수직 진동, 오일 압력, 부하율, RPM, 전력의 8개 값. 예측 시점은 당일 종료입니다.
- 이번 실험에는 출고량, 작업 지시, 센서 전일값·이동평균을 포함하지 않습니다. 설비 ID·공장·설비 종류도 세 모델의 입력에서 제외합니다. 설비 ID는 이력 집계와 점검 대상 식별에 사용합니다.
- 현재 표시 0이며 과거 30일과 미래 7일이 온전한 같은 행을 A/B/C에 사용합니다. 정답은 다음 날부터 7일 안의 표시 여부입니다.
- 공통 날짜 70%/15%/15% 분할, 각 구간 마지막 7일 제외입니다. 이번 사용 행은 학습 131,364행, 검증 28,327행입니다. 검증 예측일은 2024-02-08~2024-07-13, 총 157일입니다.
- 모든 모델은 같은 로지스틱 회귀 설정(C=1, L2, lbfgs)입니다. 결측값 보완·표준화·범주 변환은 각 모델의 학습 구간에만 맞춥니다. 점수 순위를 평가하므로 F1 판정 기준을 고르는 작업은 없습니다.

## 평가값과 결과 파일

- `pr_auc_trapezoid`: 정밀도-재현율 곡선을 사다리꼴로 적분한 면적.
- `average_precision`: AP. 재현율 증가량으로 정밀도를 가중한 값이며, 사다리꼴 PR-AUC와 구분합니다. [scikit-learn 공식 설명](https://scikit-learn.org/1.6/modules/generated/sklearn.metrics.average_precision_score.html).
- `precision_at_k`: 매일 전체 설비의 현재 정상 후보 중 점수가 높은 최대 K개의 적중 수 / 실제 점검 수. 기본 K=10입니다. 점수 동점은 정답과 무관한 설비 ID·부품 번호 순서로 고릅니다. 후보가 K보다 적으면 모두 고르고 실제 선택 수를 분모로 씁니다.
- 같은 설비·부품이 여러 날 선택될 수 있습니다. 적중 수는 **7일 정답이 1인 점검 행 수**이며 서로 다른 고장 사건 수가 아닙니다. 점검 후 수리 효과나 재점검 금지 기간을 가정하지 않습니다.

## 실제 검증 결과: 하루 10개 점검

| 실험 | PR-AUC | AP | 상위 10개 적중률 | 하루 평균 적중 수 |
| --- | ---: | ---: | ---: | ---: |
| A: 부품 정보 + 이력 | 0.5724 | 0.5725 | 64.84% | 6.48개 |
| B: 부품 정보 + 센서 | 0.5781 | 0.5782 | 62.68% | 6.27개 |
| C: 부품 정보 + 이력 + 센서 | 0.5797 | 0.5798 | 63.57% | 6.36개 |

C는 A보다 AP가 0.00735 높지만, 상위 10개 적중률은 1.27%p 낮습니다. 월별 AP와 상위 10개 적중률이 모두 높아진 것은 6개월 중 1개월입니다. 일별 상위 10개 적중률은 C가 더 좋은 날 40일, 같은 날 52일, 낮은 날 65일입니다. 따라서 **이번 설정에서는 센서의 추가 효과가 일관되게 확인되지 않았습니다.** 센서가 원천적으로 쓸모없다는 결론은 아닙니다.

2월·7월은 월 전체가 아닌 일부 날짜입니다. 미래 7일 정답과 반복 부품은 서로 관련되어 있으므로 월별 비교를 독립된 반복 실험이나 통계적 유의성으로 해석하지 않습니다. 이후 변경은 검증 구간에서 판단하고 시험 구간을 반복해서 최적화하지 않아야 합니다.
